【怎么启动】
  双击桌面上的「写作台」，或者开始菜单里搜「写作台」。
  它就是一个普通的 Windows 应用（写作台.exe）—— 不需要脚本，不需要命令行。

【它装在哪】
  %LOCALAPPDATA%\Programs\写作台\
    写作台.exe      应用本体（桌面那个快捷方式指向它）
    _internal\      运行库，别动、别删
    config.json     你的设置（仓库路径、管理密钥）
    运行日志.txt    起不来时先看这个
    _自检日志.txt   每次打包自查留下的现场

  （上面那串 %LOCALAPPDATA%\Programs\写作台 就是它，在资源管理器地址栏
    粘 %LOCALAPPDATA%\Programs 就能到。）
  （%LOCALAPPDATA% 通常是 C:\Users\<你的用户名>\AppData\Local。）

  源码在 D:\router\blog-desk\。改完代码跑一次
      python build-app.py
  就会重新打包、更新到这里，并**自己跑一次确认能用**（见下文「自查」）。
  它会顺手把 config.json 带过去，所以密钥不会丢，不用重填。

  【为什么不装在 D:\router 里】见文末「D:\router 被打了低完整性标签」一节。
    简单说：装在那里的话，exe 双击没反应。

【它是什么】
  一个给「北杉札记」用的本地编辑器。写完点「发布 → 构建 + 提交 + 推送」，
  推到 main 就等于发布（Cloudflare 会在 1–3 分钟内自动部署）。

【能干什么】
  · 写作   新建/修改/删除文章，选标签，插图片，Markdown 预览
           （文章存在 content/posts/<slug>/，图片和正文放同一个目录）
  · 说说   content/pages/talks.md；配图存进 src/assets/talks/
  · 视频   文章点「插入视频」、说说点「上传视频」，填写说明后保存
           支持 MP4 / WebM，单个最多 25 MiB；原件去重，不自动转码或播放
  · 日志   content/pages/log.md
  · 相册   看图、右键复制引用（大图 1280 / 缩略 800）、上传新图到相册
  · 标签   增加 / 删除站上的标签（改的是 src/tag-registry.ts，见下）
  · 留言   读 / 删线上的留言（管理密钥已配好，见文末）
  · 发布   跑 npm run verify（构建 + 测试），过了才提交、才推

【正文里的代码块】
  · 选中多行代码，点正文工具栏的「代码块」，会合成一个块，缩进与空行原样保留。
    没有选中内容时插入空块，光标会放在里面。
  · 默认 Python，旁边可选 JavaScript、TypeScript、JSON、Bash 或纯文本。
    光标在已有块内时选择语言，只修改这个块的语言，围栏和附加信息保留；
    再点「代码块」不会重复包裹。其他原有语言也会保留，除非主动改选。
  · 块内点「正文」可去掉围栏，恢复普通段落；Ctrl+Z 撤销，Ctrl+Y 重做，
    之前输入的撤销记录也保留。输入法组词期间请先完成组词，再设格式。
  · 代码里有反引号时会自动用更长围栏，已有反引号和波浪围栏都兼容源码编辑。
    跨代码边界、未闭合围栏，以及引用或列表中的复杂代码会提示并保持原文，
    请在源码中调整。安装版需要重新构建更新，重开旧 exe 不会读取源码界面改动。

【标签页：加一个、删一个】
  站上的标签只有一份"名册"：src/tag-registry.ts。写了名字却没登记，
  那篇文章**构建就会失败**（src/lib/schema.ts 会报「未登记的标签」）。
  所以这个页面不是"随便填个词"，它是**在改站上的源码**，规矩有两条：

  · 名字 2–5 个字，短词，不加层级（「读书」行，「读书笔记/技术」不行）。
    带空格、逗号、引号、纯数字、true/false 的一律拒 —— 那会把
    TypeScript 的字面量或 frontmatter 的 tags: [甲, 乙] 拆坏。
    同名（只差大小写也算）也会拒。
  · **正在被文章用的标签删不掉**。强行删掉，那几篇文章构建就红。
    要删就先把那些文章的 tags 改掉，再回来删。

  面板上每种标签都标了它被哪几篇文章用：
    · 灰色的「没有文章用它」= 孤儿标签 —— 现在跑构建就会红，要么给它找篇文章，
      要么删掉。
    · 底下那行提示盯着 docs/content-model.md 第 4 节那张表（它是注册表的
      人类可读镜像）。**新增标签时应用会自动在表尾补一行**；「含义边界」那列
      只能人写，所以先落一个「（待补：什么算、什么不算）」占位等你填。
      反过来，加过又删掉的标签会在表里留下一行 —— 面板会写「表格里多出：XX」，
      顺手划掉那一行即可。删标签时**不代删文档**（删是你要点头的方向）。
  · 加/删只动 tag-registry.ts 该动的那一行：注释、as const、行尾（CRLF/LF）原样保留。
    补文档也只往 §4 表尾插一行，别处一个字节不动。
    改完应用会自己把写作页的标签按钮刷新。

【几个必须知道的事】
  1. 推送现在使用普通 Git，保留和 AI 发布时相同的提交历史，不强制覆盖。
     遇到 AI 源码改动、远端领先或分叉、校验中内容变化会停止，请先完成同步。
     启动时会在本地 main 干净、历史仅落后时自动接收云端已发布内容，再开放编辑。
     使用过程中云端又有新内容，到「发布」点「同步云端内容」；「刷新」只检查。
     本地有未提交内容或真正分叉时保留现场，提示处理，不自动收起或覆盖。
     文章、说说、日志保存会检查读取版本；过期时不覆盖文件，编辑框内容也保留。
     请先复制未保存内容，再重新读取并合并。
  2. 删留言用的是站点上的管理接口，密钥两边必须是同一个值。
     密钥只存在本机的 config.json 里，不会回传给界面。
  3. 「设置」里的仓库路径改了要重开一次应用。
  4. 界面配色和字体是从站上的 src/styles/tokens.css 镜像过来的。
     博客那边改了 token，这个应用的 ui/style.css 也要跟着改，否则两边会走形。
  5. 相册新加的图，**还要把文件名写进该相册的 index.md**（含 alt），
     不然不会出现在页面上 —— 这是站上的内容模型决定的，不是 bug。

【窗口怎么用】
  · 顶部**一整条**都能按住拖动窗口（不只是左上角那块）。
  · 拖动**严格跟手**：窗口跟指针走，不多走也不少走。
    （2026-10-09 修过一次：那会儿窗口跑得比鼠标快 1.5 倍。原因是位移多乘了一次
      屏幕缩放比，而窗口坐标本来就是"逻辑像素"，和指针的坐标是同一把尺子，
      一个系数都不该乘。现在 100% 缩放和 200% 缩放下都在同一个位置。）
  · 左上角三个小圆点是 关闭 / 最小化到任务栏 / 最大化还原，
    鼠标移上去才显出颜色（例图那套 macOS 的样子）。
  · 最大化是**来回**的：点一下最大化，再点一下还原。
    （2026-10-09 修过一次：那会儿点了最大化就再也缩不回来。原因是判据用了
      pywebview 的 win.state —— 那其实是"页面级状态"的字典，跟窗口几何无关，
      每次都判成"没最大化"，于是只会反复最大化。现在直接问操作系统。）
  · 最大化状态下不再响应拖动 —— 想拖就先点绿点还原。

【出问题时的自查顺序】
  ① 看 %LOCALAPPDATA%\Programs\写作台\运行日志.txt 有没有报错；
  ② 桌面快捷方式右键 → 属性 →「起始位置」应当是
     %LOCALAPPDATA%\Programs\写作台；
  ③ 「设置」里仓库路径对不对（要指向你博客仓库那个含 content\ 的目录）；
  ④ 侧栏底下那三行状态：显示「远端没问到」说明网络或凭据有问题；
  ⑤ 还不行就用源码目录里的「写作台（调试）.bat」启动，错误会直接打在控制台里。

  【注意】万一真窗口起不来，它会**自动改用浏览器**打开同一个界面 ——
    功能一个不少，只是少了那三个窗口键。那是降级，不是崩溃。

【打包时的自查（build-app.py 自己做的）】
  打完包它会**真的把服务起一遍**，打 /api/health，拿到 200 才算过；
  不过就直说「打出来了但起不来，别用」，并且返回非 0。
  这一步是必需的：「exe 文件在不在」和「exe 起不起来」是两回事 ——
  2026-10-09 就栽在这上面（见下一节）。
  想手动再验一次：
      写作台.exe --no-open --port 8791
  然后浏览器开 http://127.0.0.1:8791/ —— 只起服务、不开窗口，专门用来自检。

【D:\router 被打了低完整性标签（这次踩到的坑）】
  症状：exe 打出来了、双击**毫无反应**，什么都没有，也不报错。
        用控制台版跑才看到一句：
          Could not load PyInstaller's embedded PKG archive from the executable

  排查结论：跟打包没关系。同一份 exe 字节，
      C:\...\Temp\ 下能跑  ·  D:\_pytest2\ 下能跑
      D:\router\...\ 下必挂（换哪个子目录都挂）
    查 ACL 发现 D:\router 上多了一条显式 ACE：
      Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)
    它会被整棵子树继承 —— D:\router\blog（博客仓库）也一样带。
    带 Low 标签的 exe，PyInstaller 的引导程序连**自己这个文件**都打不开
    （_wfopen 返回 NULL），于是启动第一步就死了。

  已经排除的：归档/cookie 完好 · bootloader 与官方 PyPI 包逐字节一致 ·
    不是沙箱（关掉沙箱照样挂）· 不是盘符、不是长路径、不是 UPX ·
    跟目录那条 DENY DELETE_CHILD 无关（只删 DENY 不动标签，仍然挂）。
    而对那个文件执行一次 icacls /setintegritylevel Medium，**立刻就能跑**。

  → 所以现在装到 %LOCALAPPDATA%\Programs\写作台（AI 不会去动标签的常规位置），
    并且 build-app.py 装完会把标签查一遍、必要时改回 Medium，再真跑一次验证。

  【★ 2026-10-09 已处理】D:\router 整棵树（含博客仓库）那条 Low 标签**已经删掉了**。
    不是"改成 Medium"，是把标签整个移除（SetNamedSecurityInfoW +
    LABEL_SECURITY_INFORMATION，pSacl 传 NULL）。
    做法记在这儿，万一以后再冒出来可以照着重来：
      · 诊断用 _probe_label.py —— 注意：**icacls 根本不显示完整性标签**
        （它住在 SACL 里），必须用 API 读 SDDL 的 S: 段；
        而且继承来的标签长这样：S:AI(ML;OICI;NW;;;LW)，判据里漏了 AI 前缀
        就会把"有"报成"没有"（第一版就是这么错的，所以脚本自带了对照自证）。
      · 移除用 _fix_label.py（它先从根上删，再全树复核；跑一次 2 万多个条目）。
    复核结果：D:\router 及全树 21507 个条目，带标签的 **0 个**。
    ★ 顺带纠正一句旧话：这里原先写"任何 exe 放进来都会双击没反应"，实测**不是**。
      给 esbuild.exe 打上 Low 标签它照样跑（--version 正常）。
      当时挂掉的是 **PyInstaller 那种形态**（引导程序读不开自己内嵌的归档），
      所以准确的表述是"PyInstaller 打出来的 exe 会双击没反应"。

【2026-10-09 这一版改了什么】
  · 从「.bat 脚本」变成了真正的应用：写作台.exe + 桌面/开始菜单快捷方式。
    桌面上原来那个 写作台.bat 已移入回收站（要找回就去回收站）。
  · 修好了「一打开就闪一堆黑色终端」。
    根因：这个应用没有控制台，而 Windows 的规矩是"控制台子进程若父进程没有控制台，
    就给它新开一个" —— 于是每一次 git / npm 调用都闪一下，启动那几秒能连闪十几个。
    现在所有子进程统一走 lib/proc.py，都带 CREATE_NO_WINDOW。
  · 拖动窗口：窗口顶部一整条都能拖了（原来只有左侧那条深色窄边能拖）。
  · 修好了拖动时的抖动。
    根因有两条：① 用 clientX/clientY 算位移，而它相对窗口、窗口一动它自己就变，
    成了正反馈；② 用窗口坐标累加，而读窗口位置是异步的、会滞后，误差被叠起来。
    现在改用 screenX/screenY（相对屏幕）+ 绝对定位（每帧直接说"窗口该在哪"）。
  · 应用从 D:\router\写作台\ 挪到了 %LOCALAPPDATA%\Programs\写作台\ ——
    原因见上一节，不是随手换的位置。
  · build-app.py 加了两道闸：完整性标签归位 + 打包后真跑一次 /api/health。
    「打好了」这句话从此以"跑得起来"为准，不以"文件在不在"为准。

【2026-10-09 第二版改了什么（本次）】
  · 拖动窗口：修好了「窗口比鼠标快一点」。
    根因：位移多乘了一次 devicePixelRatio。窗口坐标本来就是逻辑像素（DIP）——
    pywebview 读出来时除以过缩放比、写回去时再乘回来，两头自洽；
    而指针的 screenX/screenY 在 Windows 下与 DIP 恒等。所以系数只能是 1。
    本机是 150% 缩放，于是整整快了 1.5 倍。
    现在验收测试会**显式把屏幕缩放改成 200% 再拖一遍**，要求两次发出的坐标
    一模一样 —— 旧实现会翻倍，所以这条测试真的咬得住（_t6.py 14/14）。
  · 新增「标签」页：增 / 删站上的标签（见上面那节）。
    两条红线直接做进了界面：孤儿标签标红、正在被用的标签删不掉。
    写文件是**定点替换**：只动那一行，注释与行尾原样保留（_t7.py 36/36）。
  · 有了应用图标：深场底 + 站上的 ∞ + 打字机。桌面和开始菜单的快捷方式
    跟着变成新图标（快捷方式取的就是 exe 内嵌的那个）。
  · 三处测试各自配了**变异验证**（把代码改坏，要求测试变红）：
      _mutate_t6.py  拖动 4/4 咬住
      _mutate_t7.py  标签 7/7 咬住
    其中 `_mutate_t6.py` 的存在就是因为上一版测试把代码里的错误假设
    抄进了期望值里，导致它对那个 bug 永远绿。

【2026-10-09 第三版改了什么（本次）】
  · 修好了「最大化之后缩不回来」。
    根因：判据用了 pywebview 的 `win.state`。那东西是 `webview.state.State` ——
    一个 `dict` 子类，装的是**页面级状态**（同步给 JS 的 window.pywebview.state），
    跟窗口的几何状态毫无关系，winforms 后端从不往里写。于是 `str(state)` 恒为 '{}'，
    判断恒为 False，`_maxed` 每次被重置 → **只能最大化，永远还原不了**。
    现在改成问操作系统（FindWindowW 拿句柄 + IsZoomed 读状态），
    这样连 Win+↑ 之类绕过按钮的路径也认得。
    验收：_t5.py 26/26（含真窗口），_mutate_t5.py 4/4 咬住。
    【顺带】_t5.py 原来就是 17/18 —— 上一轮给 win_pos 加了 unit 字段却没同步那条
    断言，它悄没声地红了。现在判据改成只钉关心的几个字段，不再整字典比相等。
  · 「标签」页：新增标签时**自动往 docs/content-model.md §4 的表尾补一行**
    （站上授权），并把文档补齐（教程 / 工具早就登记了、表格里一直漏着）。
    删标签仍然不代删文档，但面板会把"表格里多出来的一行"报出来。
    验收：_t7.py 50/50，_mutate_t7.py 11/11 咬住。
  · D:\router 那条 Low 完整性标签**删掉了**（全树 21507 个条目复核，0 个）。

【2026-10-09 第四版改了什么（本次）：推图片推不上去】
  · 症状：点「构建 + 提交 + 推送」，推一张**截图**时报
      「上传后的内容树与本地 HEAD 不一致」—— 为免留下半截状态，已中止（远端未改动）。
    那句报错是应用自己装的保险丝（推完核对远端的 tree 是否等于本地的），
    它拦对了 —— 但真错在上游：**读文件的时候就把图片读坏了**。
  · 根因：读 git 输出的那个函数带着 text=True, errors="replace"。
    "非法 UTF-8 字节换成 U+FFFD"这一下，把 PNG 里的字节改了 —— 一张 104373 字节的图
    被读成 185779 字节、103664 处不同。字节一变，文件的内容哈希（blob sha）就变，
    树也就变，保险丝立刻跳闸。**全程一句报错都没有。**

【桌面图标换了却不变（2026-10-09 站主亲历）】
  先记一个反直觉的事实：**在桌面按 F5 换不掉图标**，改名字也常常没用。
  原因：这两步只是让资源管理器**把缓存重读一遍**；
  而当时**缓存里存的就是旧图标**（数据本身是错的），读一百遍还是旧的。
  ★ 所以"刷新"解决不了"数据是错的" —— 得先分清两件事：
      图标缓存（iconcache_*.db 里的数据，文件本身对不对）
        vs
      刷新重绘（让 Explorer 再读一遍、桌面再画一遍，画出来的跟数据一不一致）
  怎么分清（两个都是只读的检查）：
      · 问文件本身 → PrivateExtractIconsW，看这个 exe 里内嵌的是什么图标
      · 问 shell    → SHGetFileInfoW，看它现在**会显示**什么（走缓存）
  这一轮查下来：文件对了、快捷方式对了、缓存也已经更新成新的了，
    **只剩 Explorer 进程内存里还攥着旧副本**。
  按力度递进：
    1. Win+R → `ie4uinit.exe -show` 回车（一秒，多数情况够用）
    2. 任务管理器（Ctrl+Shift+Esc）→ 找到「Windows 资源管理器」→ 右键 → **重新启动**
    3. 注销重登 / 重启
    4. 结束 explorer.exe，删 %LOCALAPPDATA%\Microsoft\Windows\Explorer\iconcache_*.db，
       再启动 explorer
    ★ 只想让某个快捷方式换图标：把它**改个名**（加个空格再删掉）Windows 会立刻重读 ——
      这招对"数据已经是对的、只是进程没重画"的情况才管用。

【2026-10-09 第五版改了什么（本次）：刚启动时点它有几率卡死】
  · 症状：双击启动后**趁窗口刚出来点它**，有时候会没反应（窗口在、点不动）。
    过一会儿，或者干脆重启一次，又好了 →「有几率」。
  · ★ 根因不是"点"，是**启动时的竞态**（"点"只是恰好撞上它）：
      pywebview 注入 JS 桥的时候，会在一个**新建的非UI 线程**里遍历我们传进去的
      那个对象（它要靠这个把方法列给页面）。而我们以前把**窗口对象本身**
      挂在了那个对象上（叫 `win`，没有下划线），于是它一路摸到了 .NET 的
      WebView2 控件 —— 而那个控件**只准 UI 线程碰**。
      运行日志里能数出来：17 次启动、16 次递归爆栈、69 次
      「CoreWebView2 can only be accessed from the UI thread」，
      但**没有一次降级到浏览器** → 窗口每次都起来了，只是有时候变卡。
  · 修法：窗口引用改名成 `_win`（**下划线开头**）。
      下划线不是命名风格，是**判据** —— pywebview 遍历时会
      `if name.startswith('_'): continue`，直接跳过它，所以它摸不到我们的窗口。
    → **别"顺手"把 `_win` 改回 `win`**。app.py 里那一行注释写明了为什么。
  · 顺带修好了：以前真有一个洞 —— 拿"改完的源码"去比字节时，
      跨行锚点因为文件是 CRLF 行尾而**一次都没匹配上**，于是那三条变异
      被静默跳过。现已让所有变异脚本按目标文件的行尾自动归一化，
      并在开头打印用的是哪种行尾。
  · 验收：_t10.py 14/14（带反向对照：把窗口挂回无下划线的名字，判据立刻炸）、
      _mutate_t10.py 4/4 咬住、_mutate_t5.py 从「假的4/4」变成「真的 4/4」。
      其余门闩全部重跑：_t5 26/26、_t7 50/50、_t8 29/29、_t9 13/13。
  · 桌面图标那件事的结论没变：还是要**重启资源管理器**才换得掉。
